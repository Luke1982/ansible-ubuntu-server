# mailctl Implementation Plan

> **Status:** implemented. Two review rounds changed several of the interfaces below (for example `MailLog` instead of `read_lines`, `update_opendkim` instead of `apply`, Maildir functions in `mailbox`). The spec, `docs/superpowers/specs/2026-09-14-mailctl-design.md`, and the code are the reference; this plan is kept as the record of how the work was split up.


**Goal:** Build `mailctl`, a CLI on every mail server for domains, addresses, forwards, DKIM, status and spam settings, and deploy it with the `mail` role.

**Architecture:** A Python package with a `core` layer (database, files, external commands; no terminal I/O) and a `commands` layer (Typer sub-apps that prompt and render with Rich). Ansible copies the package to `/usr/local/lib/mailctl`, writes `/etc/mailctl/config.json`, and uses `mailctl dkim create` instead of the old DKIM script. Dovecot's `last_login` plugin records logins in MariaDB.

**Tech Stack:** Python 3.12+, Typer, Rich, PyMySQL, dnspython (all from Ubuntu packages), pytest, Ansible.

**Spec:** `docs/superpowers/specs/2026-09-14-mailctl-design.md`

## Global Constraints

- Runs on Ubuntu 24.04 (Python 3.12, Typer 0.9.0, Click 8.1.6, Rich 13.7.1, PyMySQL 1.0.2, dnspython 2.6.1, Dovecot 2.3) and Ubuntu 26.04 (Python 3.14, Typer 0.19.2, Click 8.1.8, Rich 13.9.4, PyMySQL 1.1.1, dnspython 2.8.0, Dovecot 2.4).
- Only Ubuntu-packaged libraries; no pip on servers.
- Typer command parameters use `typing.Optional[...]`, not `X | None` (Typer 0.9 doesn't support it). Core code may use `X | None`.
- `core` never prints or prompts; `commands` never run SQL.
- Passwords never as arguments: prompt (hidden, twice) or `--password-stdin`.
- Every expected failure is a `MailctlError(message, hint)`.
- The full test suite passes in both pinned virtualenvs (`tests/requirements-24.04.txt`, `tests/requirements-26.04.txt`).

### Task 1: Foundation: errors, config, names, system, formatting

**Files:** create `core/errors.py`, `core/config.py`, `core/names.py`, `core/system.py`, `mailctl/__init__.py`, `core/__init__.py`, `tests/requirements-*.txt`, `tests/conftest.py`; tests `tests/test_config.py`, `tests/test_names.py`.

**Interfaces (produces):**
- `MailctlError(message: str, hint: str | None = None)` with `.message`, `.hint`.
- `SendLimit(recipients: int, seconds: int)`; `Config` frozen dataclass: `hostname`, `send_limits`, `send_limits_by_account`, `db_socket`, `db_user`, `vmail_root`, `vmail_user`, `dkim_keys`, `dkim_key_table`, `dkim_signing_table`, `dkim_user`, `mail_logs`, `sieve_after`; `Config.limits_for(address) -> tuple[SendLimit, ...]`; `config.load(path: Path | None = None) -> Config` (default `$MAILCTL_CONFIG` or `/etc/mailctl/config.json`; unknown keys and unreadable files raise `MailctlError`).
- `names.domain(value) -> str`, `names.address(value) -> str`, `names.split(address) -> tuple[str, str]`, `names.is_address(value) -> bool`.
- `system.run(*args, input=None) -> str` (raises `MailctlError` with stderr), `system.require_root()`, `system.reload(service)`, `system.server_ips() -> set[IPv4Address | IPv6Address]`.

- [ ] Write tests: valid/invalid domains (labels, hyphens, length, lowercasing), addresses, `limits_for` override and empty list, `load` of a sample JSON with path overrides, unknown key error.
- [ ] Run in both venvs, see them fail; implement; run, see them pass.
